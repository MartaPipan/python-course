#  Library Management System (OOP Python)
 Проєкт дозволяє працювати з каталогом книг різних типів (друковані та електронні), валідувати вхідні дані, присвоювати теги-жанри та виконувати пошук.
**Система керування бібліотекою** — це додаток на Python, що демонструє використання об'єктно-орієнтованого програмування (зокрема, множинного успадкування та вирішення порядку розширення методів за допомогою MRO).

##  Вирішення порядку методів за допомогою MRO

Kласи `PrintedBook` та `EBook` використовують **множинне успадкування**, переймаючи властивості від базового класу моделі книги (`Book`) та інтерфейсу публікації (`Publication`).

### Ланцюжок ініціалізації (`__init__`)
Кожен клас у ланцюжку викликає `super().__init__(**kwargs)`. Завдяки MRO, іменовані аргументи (`kwargs`) передаються послідовно через усі класи, не гублячись і не викликаючи конфліктів. Залишок аргументів врешті-решт доходить до базового класу `object`.

### Схема лінеаризації класів
Порядок пошуку атрибутів та методів для дочірніх класів виглядає так:

```text
PrintedBook ──► Book ──► Publication ──► object
EBook       ──► Book ──► Publication ──► object
```

Ви можете перевірити точний ланцюжок MRO в коді за допомогою атрибуту `__mro__`:

```python
print(PrintedBook.__mro__)
# Виведе:
# (<class 'models.PrintedBook'>, <class 'models.Book'>, <class 'models.Publication'>, <class 'object'>)
```

###  Динамічна валідація року видання

У системі реалізовано автоматичний захист від внесення книг, які «ще не були надруковані». Замість жорсткого закріплення поточного року в коді (hardcoding), додаток використовує модуль `datetime` для динамічної перевірки.

Логіка роботи конструктора класу `Book`:
```python
from datetime import datetime

current_year = datetime.now().year
if year > current_year:  
    raise ValueError(f"Рік видання не може бути в майбутньому (більше ніж {current_year})!")
```

**Чому це важливо для архітектури проєкту:**
1. **Актуальність без оновлення коду:** Коли настає новий календарний рік, система автоматично дозволить реєструвати книги нового року видання, не потребуючи рефакторингу чи втручання розробника.
2. **Точність тестів:** Як видно з логіки тестування, спроба створити книгу 2028 року миттєво перехоплюється винятком, де динамічно підставляється поточний ліміт: `(більше ніж 2026)`.


### Динамічний поліморфізм методів
Метод `delivery_description()` визначений у класі `Publication` як дефолтний, але він динамічно перевизначається (overridden) у класах `PrintedBook` та `EBook`. 

Завдяки правильному порядку в MRO, Python спочатку шукає реалізацію в самому дочірньому класі (`PrintedBook`/`EBook`), забезпечуючи специфічну поведінку для кожного типу видання:
- Для **PrintedBook**: Повертає опис доставки поштою.
- Для **EBook**: Повертає посилання на завантаження.

##  Функціонал
- **Множинне успадкування:** Використання `super().__init__(**kwargs)` для безпечної ініціалізації сутностей у ланцюжку класів.
- **Жорстка валідація даних:** Захист від порожніх рядків у назвах, авторах та жанрах; перевірка типу та значень для років видання (заборона майбутнього часу, від'ємних значень чи логічних типів `bool`).
- **Різні типи видань:** Підтримка друкованих книг (`PrintedBook` із підрахунком сторінок) та електронних носіїв (`EBook` із посиланнями на завантаження).
- **Розумний пошук:** Реєстронезалежний (case-insensitive) пошук книг у бібліотеці за частиною імені автора або за точним збігом жанру.
- **Захист від дублікатів:** 
  - У пам'яті: Обробка кастомного винятку `DuplicateBookError` при спробі повторно додати один і той самий об'єкт книги.
  - У файлі бази даних: Інтелектуальна перевірка наявних записів у CSV за парою (назва, автор) для запобігання дублювання рядків при повторних запусках.
- **Експорт у CSV:** Автоматичне створення, фільтрація унікальних записів та структурування каталогів даних без накопичення зайвих порожніх рядків.

## Приклад використання та демонстрація роботи

Запуск головного скрипту додатка (`demo.py`) ініціює комплексну перевірку функціоналу, валідації даних та обробки винятків.

### 1. Створення каталогу та незалежність атрибутів
При ініціалізації об'єктів виконується автоматичне приведення типів (наприклад, числова назва `1984` стає рядком). Списки тегів повністю ізольовані між екземплярами:

```text
Порожня бібліотека: []
--- 1. Демонстрація створення книг із валідацією для порожньої бібліотеки ---
Книга 1 (Printed, числова назва): '1984' — Джордж Орвелл (1949) | Жанри: []
Книга 2 (EBook): 'Колгосп тварин' — Джордж Орвелл (1945) | Жанри: []

--- 2. Перевірка незалежності списків tags (додаємо унікальні жанри) ---
Книга 1 (Орвелл) після тегів: '1984' — Джордж Орвелл (1949) | Жанри: ['антиутопія', 'класика']
Книга 2 (Орвелл, має бути без тегів): 'Колгосп тварин' — Джордж Орвелл (1945) | Жанри: []
Списки tags незалежні для кожного об'єкта
```

### 2. Реєстронезалежний пошук (Case-Insensitive)
Пошукова система нормалізує пробіли та регістр символів як для авторів, так і для тегів:

```text
Шукаємо автора 'дЖоРдЖ оРвЕлЛ':
  Знайдено: '1984' — Джордж Орвелл (1949) | Жанри: ['антиутопія', 'класика']
  Знайдено: 'Колгосп тварин' — Джордж Орвелл (1945) | Жанри: []

Шукаємо книги з жанром 'ФЕНТЕЗІ':
  Знайдено за жанром: Гаррі Поттер і філософський камінь (автор: Джоан Роулінг)
  Знайдено за жанром: Гобіт, або Туди і назад (автор: Джон Р. Р. Толкін)
```

### 3. Робота тригерів валідації та винятків
Система безпеки коду перехоплює некоректні типи даних, від'ємні значення, порожні рядки, майбутній час (обмежено поточним 2026 роком), а також дублювання об'єктів у пам'яті через кастомний `DuplicateBookError`:

```text
Тест 1: Спроба створити книгу з порожніми пробілами замість назви...
  Перехоплено помилку назви: Заповніть назву книги

Тест 4: Спроба передати логічне значення True замість року...
  Перехоплено помилку bool-року: Рік має бути коректним числом!

Тест 6: Спроба створити книгу з майбутнього (2028 рік)...
  Перехоплено помилку майбутнього часу: Рік видання не може бути в майбутньому (більше ніж 2026)!

Перевірка DuplicateBookError:
  Додаєм існуючий екземпляр книги (book3) удруге...
  Результат DuplicateBookError: Об'єкт книги 'Гаррі Поттер і філософський камінь' вже додано в цю бібліотеку
```

### 4. Демонстрація динамічного поліморфізму (MRO в дії)
Завдяки реалізації єдиного інтерфейсу та налаштованому порядку MRO, додаток може ітеруватися по всьому списку книг та викликати метод `.delivery_description()` без явного кастингу типів або перевірок `isinstance()`:

```python
# Код виклику поліморфного методу для всіх книг у базі
for book in library.books:
    print(f"  {book.delivery_description()}")
```

**Результат у консолі:**
```text

  Електронна книга 'Колгосп тварин' доступна за посиланням: https://library.com
  Друкована книга 'Гаррі Поттер і філософський камінь' (320 стор.) буде доставлена поштою або кур'єром.
  Електронна книга 'Гобіт, або Туди і назад' доступна за посиланням: https://library.com
  Друкована книга 'Кобзар' (450 стор.) буде доставлена поштою або кур'єром.
```
