Абстрактний клас — це особливий клас в об'єктно-орієнтованому програмуванні, який створений виключно для того, щоб бути батьком для інших класів.
Створювати об'єкти (екземпляри) безпосередньо з абстрактного класу заборонено. Це залізобетонний шаблон, креслення або архітектурний план для майбутніх дочірніх класів.
Щоб зрозуміти це раз і назавжди, давай розберемо просту життєву аналогію.

🏛️ Аналогія з життя: Поняття «Тварина» або «Транспорт»

Уявіть, що я підходжу до вас і кажу: «Намалюйте мені, будь ласка, транспорт».
• Ви запитаєте: «Який саме? Автомобіль? Літак? Велосипед? Потяг?»
• Я наполягаю: «Ні, не треба автомобіль. Намалюйте мені просто транспорт у чистому вигляді».
Це неможливо! Бо слово «транспорт» — це абстрактне поняття. У реальному світі не існує фізичного об'єкта під назвою «просто транспорт». Але ми використовуємо це слово як спільний шаблон для реальних, конкретних речей, які мають колеса, двигун та вміють їздити.
Ось у програмуванні:
• Транспорт — це абстрактний клас. Він задає загальні правила (усі мають вміти заводитися та їхати).
• Автомобіль, Літак — це конкретні класи (підкласи), які ми створюємо на основі абстрактного. Вони вже реальні, і їхні об'єкти створювати можна.

💻 Навіщо це потрібно в Python і як це працює?

Програмісти використовують абстрактні класи як суворий контракт (договір) між архітектором програми та іншими розробниками.
Уявіть, що ви пишете гру, і вам потрібно, щоб усі монстри вміли атакувати. Ви створюєте абстрактний клас Monster. За допомогою спеціальної позначки @abstractmethod ви примусово зобов'язуєте кожного, хто буде писати нових монстрів, реалізувати метод attack().
python
from abc import ABC, abstractmethod

# 1. Створюємо АБСТРАКТНИЙ КЛАС
# (Він обов'язково успадковує магічний клас ABC - Abstract Base Class)
class Monster(ABC):
    
    @abstractmethod
    def attack(self):
        """Всі підкласи ЗОБОВ'ЯЗАНІ розписати цей метод зсередини"""
        pass

# ==========================================

# 2. Створюємо конкретний підклас
class Zombie(Monster):
    def attack(self):
        return "🧟 Зомбі кусає за руку!"

# 3. Створюємо ще один конкретний підклас, але "ЗАБУВАЄМО" написати атаку
class Dragon(Monster):
    def fly(self):
        return "🐉 Дракон летить у небо."

🛡️ Що станеться, якщо запустити цей код?

А тепер подивимося, як Python захищає архітектуру нашої програми:
1. Спроба створити «пустушку» з абстрактного класу:python
monster = Monster() 
# ❌ Помилка! TypeError: Can't instantiate abstract class Monster
Use o código com cuidado.
Python каже: «Ні, друже, просто абстрактного монстра не існує. Створи конкретного!»
2. Спроба створити Зомбі:python
zombie = Zombie()
print(zombie.attack()) # ✅ Успішно! Виведе: 🧟 Зомбі кусає за руку!

3. Спроба створити Дракона (якому ми забули додати метод attack):python
dragon = Dragon()
# ❌ Помилка! TypeError: Can't instantiate abstract class Dragon with abstract method attack
Use o código com cuidado.
Python каже: «Стоп! Ти вказав, що Дракон — це Монстр. А за контрактом усі монстри мають вміти атакувати! Поки не напишеш метод attack всередині класу Dragon, я не дозволю створити цей об'єкт!»

📌 Головний підсумок:

Абстрактний клас — це інструмент наведення ладу у великому коді. Він потрібен для:
1. Заборони створення безглуздих об'єктів-пустушок (як-от «просто транспорт» або «просто фігура»).
2. Примусу інших розробників писати обов'язкові методи (на кшталт area(), pay(), attack()) у дочірніх класах, гарантуючи, що код не зламається під час роботи сайту чи гри.
