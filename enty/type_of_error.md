# Помилки в Python (Exceptions)
З використанням {error}

python
try:
    number = 10 / 0
except Exception as error:
    print(f"❌ Сталася помилка: {error}")

• Плюс: Програма не впаде, а на екрані з'явиться чітке пояснення від самого Python:
❌ Сталася помилка: division by zero

| **`SyntaxError`** | Друкарська помилка в правилах мови. | `if x = 5:` *(одне `=` замість двох)* | Перевірити розділові знаки (`:`, `()`, `[]`, `==`). |
| **`IndentationError`** | Зламані відступи (пробіли або табуляція). | `if True:`<br>`print("Hi")` *(немає відступу)* | Поставити 4 пробіли (або Tab) всередині `if`, `for`, `def`. |

## 🔒 Робота з ресурсами: `with` проти `finally`

Коли ви працюєте з файлами, мережею або базами даних, ресурси потрібно обов'язково закривати, щоб не перевантажувати пам'ять комп'ютера.

### 📄 1. Для файлів: ЗАВЖДИ використовуйте менеджер контексту `with`
Конструкція `with` автоматично закриває файл, навіть якщо всередині коду сталася критична помилка. Це робить код коротким та безпечним.

```python
# 👍 ПРАВИЛЬНО (Python сам закриє файл)
with open("students.csv", "r", encoding="utf-8") as file:
    data = file.read()
    # працюємо з файлом...
# Тут файл ВЖЕ закритий
```

### ⚙️ 2. Для інших ресурсів: використовуйте `try - finally`
Блок `finally` виконується **в будь-якому випадку** (неважливо, впала програма з помилкою чи завершилася успішно). Його ідеально використовувати для:
* Закриття з'єднань із **базами даних** або вебсокетами.
* **Журналювання (Logging):** наприклад, записати в лог-файл "Програма завершила роботу", навіть якщо сталася аварія.

```python
#  Приклад використання для очищення або логування
try:
    print("Підключаємося до бази даних...")
    # Код, який може зламатися
    result = 10 / 0  
except ZeroDivisionError:
    print("Ой, сталася помилка ділення на нуль!")
finally:
    # Цей блок виконається ОБОВ'ЯЗКОВО
    print("Примусове закриття з'єднання з БД та запис у журнал.")
```


import csv

# Наш список обов'язкових колонок для валідації
REQUIRED_HEADERS = ["name", "attended", "total"]
issues_list = []

# 1. Використовуємо 'with' для безпечного відкриття файлу
with open("students.csv", "r", encoding="utf-8") as file:
    # Читаємо файл як словник: кожен рядок — це {"колонка": "значення"}
    reader = csv.DictReader(file)
    
    # 2. Цикл для перебору всіх рядків таблиці
    for index, row in enumerate(reader, start=1):
        
        # Перевірка: якщо рядок абсолютно порожній — пропускаємо його
        if not any(row[key].strip() for key in REQUIRED_HEADERS if row.get(key)):
            continue
            
        # Безпечно дістаємо та очищаємо текстові дані
        name = row.get("name", "").strip()
        raw_attended = row.get("attended", "").strip()
        raw_total = row.get("total", "").strip()
        
        # Якщо немає імені студента — це критично для цього рядка
        if not name:
            issues_list.append(f"Рядок {index}: Помилка -> Ім'я студента порожнє")
            continue  # переходимо до наступного студента
            
        # 3. Блок try-except для захисту від помилок конвертації чисел (ValueError)
        try:
            # Намагаємося перетворити текст на цілі числа
            attended = int(raw_attended)
            total = int(raw_total)
            
            # Захист від ZeroDivisionError: перевіряємо, чи загальна кількість занять не 0
            if total == 0:
                raise ZeroDivisionError
                
            # Рахуємо відсоток відвідуваності
            percentage = (attended / total) * 100
            print(f"Студент: {name} | Відвідуваність: {percentage:.1f}%")
            
        except ValueError:
            # Цей блок врятує програму, якщо в клітинці буде текст або порожнеча '' (base 10)
            issues_list.append(f"Рядок {index} ({name}): Помилка -> Некоректні цифри у відвідуваності ('{raw_attended}' або '{raw_total}')")
            
        except ZeroDivisionError:
            # Рятує, якщо total == 0
            issues_list.append(f"Рядок {index} ({name}): Помилка -> Загальна кількість занять дорівнює 0 (ділення на нуль)")

# 4. Після виходу з 'with' файл закрився автоматично. Виводимо звіт про помилки.
print("\n--- ЗВІТ ПРО ПРОБЛЕМИ В ТАБЛИЦІ ---")
if issues_list:
    for issue in issues_list:
        print(issue)
else:
    print("Усі дані оброблено успішно, помилок не знайдено!")

# Що таке raise?

Команда raise дозволяє вам самостійно (вручну) викликати помилку, якщо користувач чи інша функція порушили правила вашої програми (контракт).
• Правило гарного тону: Повідомлення всередині помилки має чітко пояснювати, яке саме правило порушено, а не просто писати «Error».
python
def set_score(score):
    if not 0 <= score <= 100:
        # Вручну викликаємо стандартну помилку ValueError
        raise ValueError(f"Некоректний бал: {score}. Має бути від 0 до 100")
    return score
Use o código com cuidado.

2. Коли створювати свій тип помилки (Власні винятки)?

Стандартних помилок (як ValueError, TypeError) зазвичай вистачає для перевірки чисел чи тексту. Але коли порушується бізнес-логіка програми (наприклад: закінчилися гроші на картці, користувач забанений, дедлайн пройшов), варто створити власну помилку.
python
# Створюємо власну помилку (назва класу завжди закінчується на Error)
class EnrollmentClosedError(Exception):
    """Реєстрацію неможливо продовжити після дедлайну."""

def enroll(is_open):
    if not is_open:
        # Викликаємо саме нашу унікальну помилку
        raise EnrollmentClosedError("Реєстрацію на курс уже закрито!")
Use o código com cuidado.
💡 Важлива порада з тексту: Не створюйте новий клас для кожної дрібниці. Якщо проблема просто в неправильному числі — використовуйте стандартний ValueError.

3. Де ловити помилку (try-except)?

У тексті сформульовано фундаментальне правило архітектури коду: Помилку треба ловити не там, де вона сталася, а там, де програма знає, що з нею робити.
Це ідеально описує наш з вами код для відвідуваності студентів:
1. Рівень конвертації (int()) — не знає, звідки взявся порожній рядок (із термінала чи з файлу). Він просто «кричить» через помилку: «Я не можу перетворити це на число!»
2. Наш імпортер файлів (цикл for у скрипті) — знає, що робити! Він ловить цю помилку, не дає програмі впасти, записує номер поганого рядка в issues_list і спокійно переходить до наступного студента.

## 🧮 1. Патерн "Калькулятор з повною валідацією"
Використовується для математичних обчислень, де користувач може ввести текст замість чисел або спробувати поділити на нуль.

```python
def divide_calculator():
    try:
        num1 = float(input("Введіть перше число: "))
        num2 = float(input("Введіть друге число: "))
        
        result = num1 / num2
        print(f"✅ Результат ділення: {result}")
        
    except ZeroDivisionError:
        print("❌ Помилка: Ділити на нуль (0) математично неможливо!")
    except ValueError:
        print("❌ Помилка: Введено текст! Будь ласка, використовуйте лише цифри.")
```

## 📄 2. Патерн "Ізольований виняток" (Тільки для FileNotFoundError)
Ловить суто відсутність файлу на диску. Усі інші системні аварії пройдуть далі (піднімуться вище), щоб розробник міг побачити справжню технічну проблему.

from pathlib import Path

def read_config_file():

## 🎯 3. Патерн "Захист бізнес-логіки" (`if-raise ValueError`)
Якщо дані правильного типу (число), але виходять за межі здорового глузду (правила задачі), ми вручну викидаємо помилку з чітким описом правила.

```python
def calculate_discount_price(original_price, discount_percent):
    # Контракт функції: відсоток має бути в межах від 0 до 100
    if not 0 <= discount_percent <= 100:
        raise ValueError(f"Порушення контракту: знижка не може бути {discount_percent}%. "
                         f"Дозволений діапазон відсотків: від 0 до 100.")
    
    return original_price * (1 - discount_percent / 100)
```

## 🛡️ 4. Патерн "Користувацька валідація" (Заміна небезпечного `assert`)
**Правило:** Інструкцію `assert` використовують тільки для тестів розробника. Для реальних даних користувача її використовувати **заборонено**. Замість неї використовуємо `if-raise`.

```python
def check_registration_age(user_age_text):
    try:
        # 1. Захист від тексту
        age = int(user_age_text)
        
        # 2. Перевірка правила (Заміна assert user_age >= 18)
        if age < 18:
            raise ValueError(f"Доступ обмежено. Ваш вік: {age}. Дозволено лише з 18 років.")
        
        # 3. Перевірка на адекватність
        if age > 120 or age < 0:
            raise ValueError(f"Введено нереалістичний вік: {age}.")
            
        print("🎉 Реєстрацію успішно пройдено!")
        return True
        
    except ValueError as e:
        # Ловимо і помилку тексту від int(), і наші ValueError від raise
        print(f"❌ Відхилено: {e}")
        return False
```

## 🧬 5. Анатомія архітектури власних винятків (`Custom Exceptions`)

Коли стандартних помилок мало, ми створюємо свій унікальний клас. Ось його структура:

```python
# 1. Назва нового типу: EnrollmentClosedError
# 2. Базовий тип: Exception (всередині дужок)
class EnrollmentClosedError(Exception):
    """Реєстрацію неможливо продовжити після дедлайну."""

# 3. Місце для команди `raise`
def enroll(is_open):
    if not is_open:
        # Викликається безпосередньо в точці порушення правила бізнес-логіки
        raise EnrollmentClosedError("Реєстрацію на курс уже закрито!")

# 4. Можливе місце для блоку `except`
# Використовується на найвищому рівні інтерфейсу (наприклад, у кнопці сайту),
# щоб зловити помилку та красиво написати користувачеві: "Запис завершено".
```
